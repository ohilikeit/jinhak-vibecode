# 대표 시연 런북 — "회사를 아는 AI" (jinhak-harness)

> 목적: 비개발자가 이 시스템을 **어떻게 쓰는지**를 대표 앞에서 10분 안에 시연.
> 전략: Layer 1·2(회사 맥락/데이터 가져오기)는 **로컬/OneDrive 실데이터로 안전하게**,
> 정식 연결(MCP)은 **"승인 필요" 실화면으로 의사결정 요청**.
> 작성: 2026-06-03 · 환경: Claude Code (이 레포에서 실행 권장)

---

## 0. 결론 한 줄 (시연 전 대표께 각인시킬 메시지)
> **"더 똑똑한 AI를 사는 게 아니라, 우리 회사를 아는 AI를 만든다."**
> 이미 가진 Microsoft 365 위에, 추가 비용 0원, 읽기 전용·권한 분리로 안전하게.

---

## 1. 사전 점검 (시연 30분 전 — 반드시 1회 리허설)

### 1-1. 실행 위치
- **이 레포 폴더에서 Claude Code를 연다.** (`/jinhak:context-sync` 가 프로젝트 커맨드로 여기 있음)

### 1-2. npm 슬래시 커맨드 등록 (`/jinhak:start` 등 사용하려면)
```bash
jinhak-harness --version          # v0.1.3 확인 (Windows: 새 터미널에서)
jinhak-harness register           # 6 호스트에 /jinhak:* 등록
```
- 등록 후 **Claude Code 완전 종료 → 재실행** (슬래시 커맨드 새로고침).
- 확인: 채팅창에 `/jinhak:` 입력 시 start/build/verify/context-sync 가 뜨는지.

### 1-3. 컨텍스트 소스 결정 (둘 중 하나)
- **(A) 로컬 샘플 — 기본/가장 안전**: 아무것도 안 해도 됨. `demo/jinhak-context/` 사용.
- **(B) OneDrive 실데이터 — 진짜감**: 진학사 SharePoint 라이브러리를 OneDrive로 동기화 후
  ```bash
  export JINHAK_CONTEXT_PATH="/mnt/c/Users/<계정>/OneDrive - 진학사/jinhak-context"
  ```
  (Windows Claude Code면 그 OS의 환경변수로 설정)

### 1-4. 샘플 내용 교체 (권장)
- `demo/jinhak-context/` 안의 4개 `.md`는 **시연용 더미**다. 가능하면 **실제 본부/팀/프로젝트 목표로 교체**하면 설득력이 크게 오른다. (구조만 두고 내용만 바꾸면 됨)

### 1-5. 리허설
- 아래 2장 시나리오를 **처음부터 끝까지 1회** 돌려본다. context-sync 출력·CLAUDE.md 주입·후속 질문 답변까지 확인.

## 2. 시연 시나리오 (10분)

### 장면 ① "AI는 우리 회사를 모른다" (문제 제기, 30초)
- 빈 질문을 던진다: **"우리 팀 올해 목표에 맞춰 이번 분기 우선순위 정해줘"**
- (아직 context-sync 전) → AI가 **일반론**으로 답함.
- 멘트: *"보시다시피 AI는 똑똑하지만 **우리 회사를 모릅니다.** 이게 AI 도입이 안 먹히는 진짜 이유입니다."*

### 장면 ② Layer 1 — 회사 맥락 가져오기 (2분) ★핵심
- 입력: **`/jinhak:context-sync`**
- 기대 출력(요약):
  ```
  📥 회사 컨텍스트 가져오기 완료 (읽기 전용)
  🏢 본부 — 전사CEO직속 / 2026 방향: 4대 서비스 전반 AX…
  👥 팀  — AX팀 / OKR: 비개발자 AI 자립도 30→70%…
  📁 프로젝트(2): 전사 AX 전환 / 수시 합격예측 모델 개발
  ✅ 이제 AI가 회사를 압니다.
  ```
- 멘트: *"직원은 아무것도 안 했습니다. 회사가 SharePoint에 적어둔 본부·팀·프로젝트 목표를
  **읽기 전용으로 가져와** AI에 깔았을 뿐입니다."*

### 장면 ③ "이제 AI가 회사를 안다" (1분) ★대비 효과
- 장면 ①과 **똑같은 질문**을 다시: **"우리 팀 올해 목표에 맞춰 이번 분기 우선순위 정해줘"**
- → AI가 **AX팀 OKR(도입률 30→70%, 자동화 50건)·진행 프로젝트(전사 AX 전환·수시 합격예측 모델)**를 근거로 답함.
- 멘트: *"같은 AI, 같은 질문. 차이는 **회사 맥락**뿐입니다."*

### 장면 ④ 첫 프로젝트 시작 + 인터뷰 모드 (3분)
- 입력: **`/jinhak:start`** → 5문항 직군 인터뷰 진행 (직군·반복업무·도구 등 답변)
- 멘트: *"비개발자는 '무엇을 하려는지'만 답하면 됩니다. 나머지(직군 프로파일·자동화 설계)는 도구가 합니다."*

### 장면 ⑤ 실제 산출물 (2분, 선택)
- `demo/` 또는 `inbox/`에 PDF/엑셀 샘플을 두고 **`/jinhak:build 채용공고 정리`** 류 실행 → `output/` 산출물.
- 멘트: *"회사 맥락 위에서 실제 결과물까지 한 줄로."*

### 장면 ⑥ "정식 연결은 이렇게" — MCP 의사결정 요청 (1.5분) ★대표 액션
- **오늘 막힌 화면 캡처**(관리자 승인 필요)를 띄운다.
- 멘트: *"오늘 시연은 로컬 시드로 보여드렸지만, 정식 연결은 **Microsoft 로그인 → SharePoint 읽기**입니다.
  방금 실제로 시도했더니 이 화면이 떴습니다 — **우리 보안이 제대로 작동한다는 증거**입니다.
  외부 앱이 함부로 회사 데이터를 못 읽고 관리자 승인에 막혔습니다.
  정식 도입은 **IT가 '읽기 전용 앱 1건'만 승인**하면 켜집니다."*

## 3. 대표께 요청할 의사결정 3가지 (마무리 슬라이드)
1. **IT 협조** — SharePoint 전용 공간 1개 + 읽기 전용 연결(앱) 1건 승인 (보안 위험 없는 읽기 전용)
2. **담당자 지정** — 본부·팀별 "회사 맥락 문서"를 누가 관리할지
3. **방향 승인** — 3단(맥락→데이터→도구) 구조로 전사 확대 진행

## 4. 리스크 & 복구 (Plan B)
| 문제 | 복구 |
|---|---|
| `/jinhak:context-sync` 안 보임 | 이 레포에서 Claude Code 실행 중인지 확인 (프로젝트 커맨드) |
| `/jinhak:start` 안 보임 | `jinhak-harness register` 후 Claude Code 재시작 |
| OneDrive 경로 못 읽음 | `JINHAK_CONTEXT_PATH` 해제 → 로컬 `demo/jinhak-context` 자동 폴백 |
| context-sync 출력이 빈약 | 샘플 `.md` 내용이 들어있는지 확인 (`find demo/jinhak-context -name '*.md'`) |
| 라이브 질문 답이 어긋남 | 장면 ③ 질문을 컨텍스트에 있는 키워드(OKR·프로젝트명)로 구체화 |

## 5. 절대 하지 말 것
- 라이브에서 **MCP 로그인 재시도** (admin 승인 벽 → 시간 잡아먹고 흐름 깨짐). 캡처로만 설명.
- 산출물에 **개인정보**(지원자 연락처 등) 노출.
- "이미 다 구현됐다"는 과장. 솔직하게: **3층 도구=완성, 1·2층 연결=IT 승인 대기**.

## 부록: MCP 정식 연결 경로 (데모 후 IT와 진행)
- **방법 B 권장**: 진학사 전용 **single-tenant 읽기앱** 1건 등록(`Sites.Read.All`/`Files.Read`)
  → admin consent → `ms-365-mcp-server`를 `MS365_MCP_CLIENT_ID`/`MS365_MCP_TENANT_ID`로 연결.
  최소 권한·회사 전용이라 보안 설명이 깔끔. (상세: `docs/architecture/ENV_SETTING.md`)
- 오늘 검증 결과: 외부 앱(Softeria) user consent는 테넌트 정책상 **차단**됨 → 관리자 승인 필수 확인.
